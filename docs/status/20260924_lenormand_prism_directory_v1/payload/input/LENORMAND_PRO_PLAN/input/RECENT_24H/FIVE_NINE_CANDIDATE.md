## 3. 五牌：THREE 不作退路

模式沿用 `LayoutMode.FIVE_CARD_LINE`；未来 slug 候选 `ln-five-site-v1`，未注册开放。显示由左到右五槽，代码索引从 0 开始；用户界面从第 1 张开始。

|代码槽|用户槽|本站角色|明确边界|
|---|---|---|---|
|0|1|现状|限定当次议题，不从用户长期画像补事实|
|1|2|助力|必须说明适用条件，不能直接等同成功保证|
|2|3|阻力 + 中轴|必须与两翼和关系证据联合；不能把单张判词升级全局|
|3|4|隐藏变量|是需要核实的变量，不是断言用户隐瞒事实|
|4|5|建议|从条件与路径推出，不保证未来、不得自动套塔罗末阶段职责|

候选关系保留 7 个实例：一条 ORDERED_LINE_SEQUENCE `(0,1,2,3,4)`；四条 ORDERED_ADJACENCY `(0,1),(1,2),(2,3),(3,4)`；MIDDLE_PIVOT `(2,)`；FULL_MEMBER_SET `(0,1,2,3,4)`。去重键至少为 layout_version、kind、canonical slots、direction；有向成员不能按字母排序消去方向。全成员集的重复归一化与有向线分开，不借“同一组牌”混同两者。

不额外启用镜像 `(0,4)/(1,3)`、时间线、隐藏对角或自动反向对读。要新增必须有独立方法、scope、任务和验收；没有这些不会阻断已完整的四邻接路径。

### 3.1 中轴不独断：两级校验

**结构级**：保留四邻接、全体覆盖；第三槽至少参与多条关系；至少存在完全不经第三槽的关系，且其他四槽都在非中轴关系中得到覆盖。L 的 MIN_PIVOT_PARTICIPATION=2 和 `assert_pivot_is_not_sole_authority` 只能验证这些计数。重复塞同一条关系不能满足参与度；必须先归一化去重。

**语义级**：整组主张需要来自两翼的独立可追溯支持、与阻力相关的条件、替代解释及反证路径。主判断不得只有第 3 张的一条单牌证据而其他关系都是空标签。审查样本应包含“中轴提示障碍，但助力/条件改变使路径可行”和“中轴看似可行，但非中轴证据否定关键前提”；只有获准方法能解释这种变化。synthetic 可验证支持图消费与弃用行为，真实语义必须等原文与获准样本。

不设“第三张最多 30% 权重”之类无来源数值，也不把提及五张名字当整体分析证明。

## 4. 九牌：中心/周围与横纵关系

模式沿用 `LayoutMode.NINE_CARD_GRID_3X3`；未来 slug 候选 `ln-nine-site-v1`。槽映射固定为行优先：

```text
0  1  2      用户显示：1 2 3
3  4  5                4 5 6
6  7  8                7 8 9
```

中心为 4；周围集合为 `{0,1,2,3,5,6,7,8}`。L 的 CENTER_RING tuple 是集合登记顺序，不是顺时针方向，不得沿该 tuple 虚构环路或因果链。正交邻居为 `{1,3,5,7}`，角为 `{0,2,6,8}`，这些只有几何意义。

候选基本关系共 10 个：CENTER_CELL `(4,)`；CENTER_RING 周围八槽；三行 `(0,1,2),(3,4,5),(6,7,8)`；三列 `(0,3,6),(1,4,7),(2,5,8)`；两条 DIAGONAL_SUPPORT_ONLY `(0,4,8),(2,4,6)`。优先阅读组织为中心/周围→横纵→可选对角，不等于证据可信度排名或强制语义数值权重。原候选的 priority 字段只能表达处理顺序。

正交邻接若作为额外方法实例，必须显式定义：槽 a,b 的坐标曼哈顿距离 `abs(r_a-r_b)+abs(c_a-c_b)=1` 才共享边。共有 12 条无向共享边；不得把 `(2,3)` 行末跨行、`(0,4)` 对角一步或 `(0,8)` 远角当共享边。行/列有方向的解释仍须来源方法授权，不从坐标推出。

### 4.1 对角辅助的精确含义

没有获准对角方法时不消费对角语义；可以展示它是几何候选，但不输出对角牌义。已有获准的中心/周围/横纵主干完整时，不因为对角资料缺失关闭整次核心。

有具体获准对角方法时，也只能支持已经由非对角核心结构独立成立的主张；不能成为打开核心门的唯一依据、不能推翻核心主干、不能填补主干缺失。冲突时弃用/标记该辅助主张并交审查；必要主干自身冲突另按 SPEC 处理。字段 support_only=true 和 priority=4 是必要形状，不是语义充分性证明。

需反控的不只两条完整对角：相邻对角段 `(0,4),(4,8),(2,4),(4,6)` 同样不是正交邻接。L 的 `_is_diagonal_slots` 主要识别完整对角/两端点，不能把其测试通过扩大为任何几何标签错置都被拦截。新增 validator 应按坐标和 relation kind 判断，不继续罗列短黑名单。

### 4.2 中心不是唯一决定项

中心参与多条关系不等于其他八张被认真消费。语义支持图必须能展示外围/横纵对主张的限制或补充，且保留“外围反证中心初判”的样本。不能用中心一条证据建立主判，再用遍历八张名称满足计数。中心/角/行列不自动带人生阶段或心理层级意义。

## 5. 现候选需补的工程验证

1. `assemble_candidate_relations` 主要检查模式与数量，调用者还需验证每个 ref 唯一、slot 在合法范围、kind/slots/member 一致、无跨行伪邻接。不能把裸 helper 输出视为受信输入。
2. `slot_coverage` 对缺槽的检查需补多余槽、负数、越界、重复及同 ref 多槽反例。覆盖集合正确并不意味着原始输入一一对应。
3. 去重先于 pivot 参与统计；禁止通过复制实例或重命名 relation_id 伪造支持。
4. 对角分类覆盖一步对角、端点、整线；不是调整 priority 就成为合法邻接。
5. `candidate_module_is_imported_by_consumer` 的局部 ImportFrom 扫描不足以证明不可到达。CI 应检查完整已选生产包的静态 import/entrypoint 引用及从真实入口调用的默认拒绝；动态 import 无法静态证明时记录范围，运行时门仍是最后防线。
6. 任何开旗标请求不能修改来源批准、关系状态或共享运行状态；导出该候选模块也不能改变 registry 默认。
